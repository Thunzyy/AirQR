Why AirQR

When two devices should stay air-gapped.

Encode a file into animated QR codes on one screen. Scan on the other until the progress fills. The original is rebuilt on-device — fountain codes mean you need enough unique packets, not every frame in order.

Missed frames still count

RaptorQ keeps producing repair packets as the animation loops. Dropped or out-of-order frames do not stall the transfer: once enough unique packets arrive, the file is reconstructed.

Built for keys and air-gapped hosts

SSH keys, WireGuard configs, 2FA secrets, password exports. A few seconds of camera time beats a pairing prompt, a USB warning, or a guest Wi-Fi login.

Same engine, several ways in

Native apps for Android, Windows, and Debian or Ubuntu. One offline HTML file if you cannot install anything. iPhone and macOS apps are coming; the browser demo works today.

How it works

A screen becomes the cable.

  1. 01

    Choose a file

    AirQR splits it into resilient packets on your device.

  2. 02

    Show the QR animation

    No upload happens. The data travels as light between screens.

  3. 03

    Scan and rebuild

    The receiver restores the file even if a few frames were missed.

Local by design

Your files stay between your devices.

Encoding and decoding stay on the devices you control. There is no transfer cloud, and the offline HTML file can run with the network off. The data is on screen until the other camera has enough packets.
